# P4 Hailo-10H readiness (pre-hardware)

Status: **P4 Prep implemented; Hailo hardware/runtime not present or tested.** No HailoRT package, HEF, device driver, or accelerator model was installed or downloaded for this work. The current product path remains the reviewed P3 Windows Whisper CPU provider. P2 local LLM remains research-only.

## Platform and official application paths

ASUS describes UGen300 USB as a Hailo-10H accelerator with dedicated memory connected over USB-C; the separate UGen300 M.2 product is an M.2 module. These are different host attachment and discovery paths and must not be treated as interchangeable. Check the exact SKU and motherboard/host support before installing anything. ASUS product material lists Windows/Linux/Android and x86/ARM support, but that does not establish that this CodeSwitch worker, a particular host OS build, or any driver/runtime combination is supported. [ASUS UGen300 USB specifications](https://www.asus.com/us/motherboards-components/ai-accelerator/ugen/ugen300-usb-8g/techspec/), [ASUS UGen300 M.2 specifications](https://www.asus.com/jp/motherboards-components/ai-accelerator/ugen/ugen300-m2-8g/).

The official [Hailo Apps speech-recognition example](https://github.com/hailo-ai/hailo-apps/tree/main/hailo_apps/python/standalone_apps/speech_recognition) uses HailoRT `InferModel` with separate encoder and decoder HEFs. Its current README lists Hailo-8/8L/10H and Whisper `base`, `tiny`, and `tiny.en` variants, with `tiny.en` listed for Hailo-10H only. It documents Python 3.10+, HailoRT 4.20+, and audio dependencies. This is a vendor example inventory, not proof of Chinese/code-switch accuracy, compatibility with a particular UGen300 revision, or a complete CodeSwitch deployment recipe. Its resource resolver downloads model resources on first use; CodeSwitch must keep such provisioning explicit and separate from runtime.

The official [GenAI voice assistant](https://github.com/hailo-ai/hailo-apps/tree/main/hailo_apps/python/gen_ai_apps/voice_assistant) and [Voice-to-Action demo](https://github.com/hailo-ai/hailo-apps/tree/main/hailo_apps/python/gen_ai_apps/v2a_demo) show the Hailo-10H GenAI path. The latter lists Whisper Base as an HEF model, alongside a tool-selection model, an LLM, and CPU TTS; its application can execute tools. CodeSwitch will use only an approved speech-recognition API and will not reuse tool execution, automatic resource download, or LLM behavior. The V2A README lists HailoRT versions 5.1.1/5.4.0 for its own tested setup; do not combine that with the standalone app's version floor into a universal compatibility claim. Confirm the exact package, API, and model catalog for the chosen board and SDK release.

HailoRT is the runtime dependency; Hailo's model/HEF resources and any Python bindings are separately provisioned. HEF licensing/access terms, decoder assets, Whisper upstream/model terms, and any redistribution rights must be checked individually. Hailo Apps source licensing does not automatically license its models or HEFs. Do not commit HEFs or model weights.

## Current CodeSwitch contracts

- `src/contracts/speech.ts` holds the shared provider-facing result: provider/model identity, original audio SHA-256, canonical PCM WAV format, raw transcript, optional language/confidence, inference duration, runtime metadata, and explicit status/errors. Confidence is omitted unless a provider actually supplies it. Runtime metadata distinguishes `live` from `mock`.
- `src/speech/providers.ts` provides a provider registry. A new provider run creates a fresh transcript session at revision zero; it cannot inherit the prior transcript edits or transcript confirmation. Existing confirmed cards stay attached to their immutable prior source. Reanalysis still uses P1's explicit replacement flow and creates fresh draft cards requiring confirmation.
- `src/contracts/hailo-worker.ts` defines `codeswitch.hailo-asr.v1` health/transcribe JSON. Audio is sent as base64 bytes from the already selected local WAV, capped at 4,000,000 decoded bytes and 5,500,000 request bytes. The protocol has no filesystem path, shell command, URL, credential, or model-download field.
- `src/speech/hailo-worker-contract.py` is an executable protocol fixture. Normal mode reports `HARDWARE_UNAVAILABLE`; `--mock` returns a conspicuous fixed sentinel transcript with `executionMode: mock`, no device claim, and no inference. `PythonHailoMockWorkerClient` invokes only this explicit mock mode. It has bounded request/response sizes, a deadline, no shell, and suppresses worker stderr. It is never wired into the browser bridge as a live provider.
- `HailoSpeechRecognizer` validates the local WAV and source digest, checks worker health, binds response request/model/audio identifiers, verifies the returned SHA-256, and rejects malformed or mismatched outputs. It accepts an injected worker client; no HailoRT implementation is present yet. `UnavailableHailoWorkerClient` returns `HARDWARE_UNAVAILABLE`.
- `src/speech/evaluation.ts` contains the cross-provider benchmark/report contract. A provider run carries model/runtime/hardware provenance and per-audio SHA, status, transcript, constraints, raw/reviewed workflow outcomes, and latency. Mock runs are retained as `MOCK_ONLY` and produce no Live accuracy or latency metrics. Empty live input is `NOT_RUN`, not zero accuracy.

P3 Workspace/Export remains backward compatible: runtime/audio-format fields are optional when restoring older P3 v1 speech records. New Windows Whisper results and P4 providers write them. Evidence remains grounded in the transcript confirmed for that specific analysis; cards stay drafts until individually confirmed.

## Host OS, device discovery, and error handling

At hardware intake, record exact UGen300 SKU/revision, host architecture, OS/distribution and kernel, firmware/BIOS, port/slot, driver version, HailoRT and PyHailoRT versions, Hailo Apps commit/release, and model catalog revision. Confirm vendor support for that exact combination before installing packages. ASUS's platform-level OS list is not a substitute for these checks.

For discovery, record the device through the vendor tool and operating-system bus separately. On Linux, inspect USB with `lsusb`, PCIe with `lspci -nn`, then use the installed HailoRT `hailortcli scan`; on Windows inspect Device Manager/USB details and use the vendor-supported Windows HailoRT discovery tool if that SDK release provides one. A USB SKU should enumerate as USB; an M.2 SKU depends on a supported PCIe slot, lane/BIOS configuration, and driver path. The tool output must identify a Hailo device before any model request is attempted. Do not infer device presence from W7900, ROCm, LM Studio, USB power, or an adapter's mock response.

Input contract for this application is PCM16 little-endian WAV, mono, 16,000 Hz, at most 4 MB and 120 seconds. The official example's file handling/preprocessing must be checked against this canonical input at Stage II; confirm sample rate, channels, framing, padding, duration behavior, and any resampling requirements before live use. Do not invent word timestamps or confidence. Expected errors are `HARDWARE_UNAVAILABLE`, worker/protocol error, invalid/corrupt/oversized audio, timeout, cancellation, and missing model. Fail closed and keep existing cards/workspace unchanged on failure.

## Stage II real-hardware test procedure

1. Record a pre-change system inventory and a rollback plan. Confirm this is the intended host and exact USB or M.2 SKU. Keep Windows Whisper and current P3 configuration intact.
2. Check current vendor support matrices and installation instructions for the exact host OS/kernel/architecture. Obtain SDKs/firmware only through owner-authorized official sources; record checksums, version, license/EULA, and rollback steps. Do not reuse W7900/ROCm packages.
3. Install only the required official driver/HailoRT/Python binding in an isolated, documented environment after separate authorization. Verify `hailortcli scan` and HailoRT library versions. If the device is absent, mismatched, or unsupported, stop and preserve diagnostics without changing device permissions or retrying blindly.
4. Provision Whisper HEF/decoder assets only after confirming the official supported Base/Tiny variant, target architecture, model catalog release, and license. Disable implicit first-run download paths; stage and verify files explicitly. Record SHA-256 and model metadata without checking weights into Git.
5. Implement the real `HailoWorkerClient` against the installed SDK/API version, preserving the JSON contract, no-path audio protocol, strict limits, hash validation, timeout/cancel behavior, and `live` provenance. Health must report detected architecture/runtime/model readiness. Device/model failures must not fall back silently to mock or Windows Whisper.
6. Run protocol tests, then a short original WAV live smoke. Verify device/runtime identity, live-only result markers, returned SHA-256, raw text preservation, actual runtime metrics, and no automatic work-card confirmation. Exercise missing device/model, invalid audio, timeout and cancellation.
7. Use the same consented original human recording and fixed reference across Windows Whisper, Hailo Base, and Hailo Tiny. Store the audio hash, gold transcript, authorized code-switch terms/constraints, model/runtime/hardware provenance, CER/WER, terminology, negation, raw/reviewed workflow outcomes, and latency P50/P95 per provider. Keep mock, synthetic, and human recordings in separate datasets. Do not tune on the held-out evaluation set.
8. Confirm that a provider switch creates a new unconfirmed transcript revision and that work cards are regenerated as drafts from the selected transcript. Revalidate evidence spans, prohibited constraints, manual edits, confirmation and confirmed-only export. Only separately reviewed results can change product availability.

## Audio format and recovery

Do not write user filenames into process arguments. The current worker protocol passes bytes, not a path. Future live worker staging must use a private generated directory/file, verify file size/hash before inference, delete it on success/failure/cancel, and disclose that interrupted crashes may leave temporary audio. Never upload to an arbitrary URL or expose a service on LAN.

For troubleshooting, capture only sanitized command/version/status output. Keep original Whisper settings and model untouched; do not uninstall them to diagnose Hailo. If Hailo changes fail, stop the worker, restore the saved application configuration, remove only the isolated environment created for the test, verify P3 Whisper still works, and attach redacted logs to a private issue. Do not roll back system packages/drivers without the platform owner's maintenance procedure.
